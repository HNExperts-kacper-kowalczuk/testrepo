# Internationalization (i18n)

The app must be **easy to translate** from day one: adding a language is a data + XML task, not a code rewrite. Evaluation, matching, and ads stay locale-agnostic.

There are **two translation stores**. Mixing them is the usual way i18n becomes painful.

| Store | What | Format | Who updates it |
| --- | --- | --- | --- |
| **UI chrome** | Buttons, titles, errors, empty states, plurals, accessibility labels | Compose Multiplatform `composeResources` XML | Translators / Weblate |
| **Editorial content** | Ingredient comments, restriction explanations, category labels that come from the catalog | SQLite, keyed by BCP-47 locale | Editors / catalog pipeline |

INCI names, CAS numbers, GTINs, and brand names are **not translated**. They stay as printed / canonical identifiers.

---

## 1. Goals

1. **No user-facing literals in Kotlin.** Screens, ViewModels, and domain code never contain Polish or English sentences.
2. **One default locale** (`en`) that is always complete. Other locales may fall back; they must not crash.
3. **In-app language override** (system default, or a pinned locale) without reinstalling.
4. **Polish-ready plurals and grammar** from the first XML files (not `if (n == 1)` in code).
5. **Layout that survives translation**: `start`/`end` instead of `left`/`right`, no fixed-width text buttons, no concatenated sentences.
6. **Offline**: every shipped language works with airplane mode, including comments.

v1 ships **English (default)** and **Polish**. The structure must allow German, French, Spanish, etc. without schema or module changes.

---

## 2. UI chrome — Compose Multiplatform resources

Use the official Compose Multiplatform resource pipeline, not Android `R.string` and not a third-party wrapper (moko-resources) unless a later constraint forces it.

```
composeApp/src/commonMain/composeResources/
├── values/                 # default = English (always complete)
│   ├── strings.xml         # short UI copy
│   ├── strings_scan.xml    # optional split by feature
│   └── plurals.xml
├── values-pl/
│   ├── strings.xml
│   ├── strings_scan.xml
│   └── plurals.xml
├── values-de/              # later: only files that exist; missing keys fall back to values/
│   └── ...
└── files/                  # catalog.sqlite.gz — not locale-qualified
```

Access:

```kotlin
Text(stringResource(Res.string.result_title_unknown_product))
Text(stringResource(Res.string.scan_welcome, userDisplayName))
Text(pluralStringResource(Res.plurals.result_unknown_count, unknownCount, unknownCount))
```

Outside composables (ViewModel mapping, notifications):

```kotlin
getString(Res.string.camera_permission_denied)
```

Generated `Res.string.*` accessors are the **only** allowed UI string keys. Raw `"Product not found"` in a composable is a review reject.

### 2.1 Key naming

Hierarchical, stable, never reused for a different meaning:

```
scan_barcode_title
scan_inci_hint
result_rating_avoid
result_unknown_count          (plural)
permission_camera_body
ads_consent_privacy_link
```

Rules:

- Keys describe **role**, not the English words (`result_cta_evaluate`, not `evaluate_button` copied from a mockup that will change).
- **Never concatenate** fragments (`stringResource(a) + " " + stringResource(b)`). Word order differs by language. Use one string with placeholders: `%1$s`, `%2$d`.
- Prefer **named meaning in comments** inside XML so translators see context:

```xml
<!-- Result screen. Shown when OCR left unmatched INCI tokens. %1$d = count. -->
<plurals name="result_unknown_count">
    <item quantity="one">We could not identify %1$d name — results may be incomplete.</item>
    <item quantity="few">We could not identify %1$d names — results may be incomplete.</item>
    <item quantity="many">We could not identify %1$d names — results may be incomplete.</item>
    <item quantity="other">We could not identify %1$d names — results may be incomplete.</item>
</plurals>
```

Polish needs `one` / `few` / `many` / `other`. English can omit unused quantities; **do not** implement plural rules in Kotlin.

### 2.2 File split

Keep XML files small by feature so translators are not given a 400-key dump:

| File | Feature |
| --- | --- |
| `strings.xml` | App name, tab bar, common actions (Cancel, Retry) |
| `strings_scan.xml` | Camera, permissions, OCR review |
| `strings_result.xml` | Ratings, disclaimers, unknown tokens |
| `strings_catalog.xml` | Search, history, empty states |
| `strings_prefs.xml` | Avoid-list, language, pregnancy flag |
| `strings_legal.xml` | Disclaimer, consent, privacy |

Same file names in every `values-*` directory.

### 2.3 What belongs in XML vs database

| In XML | In SQLite |
| --- | --- |
| “Scan barcode”, “Not suitable for you”, tab titles | Ingredient `summary` / `detail` comments |
| Danger **labels** (`SAFE` → “Generally acceptable”) — small closed set | Per-ingredient explanations |
| Error templates with placeholders | Product names (usually untranslated proper nouns) |
| Accessibility `contentDescription` | Function-tag **display** names if the catalog grows a long list (`PRESERVATIVE` → localized label table) |

Closed enums (`DangerLevel`, `MatchMethod`) are mapped in the UI layer:

```kotlin
fun DangerLevel.label(): StringResource = when (this) {
    DangerLevel.SAFE -> Res.string.level_safe
    DangerLevel.UNKNOWN -> Res.string.level_unknown
    // ...
}
```

The domain still stores `DangerLevel.SAFE`, never `"Bezpieczny"`.

## 3. Presentation contract — `UiText`

ViewModels and use cases must not call `stringResource`. They emit a locale-independent type; Compose resolves it.

```kotlin
sealed interface UiText {
    data class Resource(
        val id: StringResource,
        val args: List<Any> = emptyList()
    ) : UiText

    data class Plural(
        val id: PluralStringResource,
        val quantity: Int,
        val args: List<Any> = emptyList()
    ) : UiText

    /** Already localized (ingredient comment from SQLite). */
    data class Catalog(val value: String) : UiText
}
```

```kotlin
@Composable
fun UiText.resolve(): String = when (this) {
    is UiText.Resource -> stringResource(id, *args.toTypedArray())
    is UiText.Plural -> pluralStringResource(id, quantity, *args.toTypedArray())
    is UiText.Catalog -> value
}
```

Domain errors are enums (`ScanFailure.PermissionDenied`), not strings. The ViewModel maps enum → `UiText.Resource`.

## 4. Editorial content — locale in the catalog

`ingredient_comment.locale` uses **BCP-47** tags: `en`, `pl`, `de`. Region variants (`pl-PL`) are allowed but v1 ships language-only tags.

Lookup chain for comments (and any other catalog copy):

```
requested locale (in-app or system)
  → exact tag (pl-PL)
  → language (pl)
  → default en
  → any remaining row for that ingredient (last resort, with a “translated automatically / fallback” flag in UI)
```

Implement as `CommentLocalizer` in `:hazards` / `:core:i18n`, not as ad-hoc SQL in each screen.

```kotlin
interface CommentLocalizer {
    fun pick(rows: List<LocalizedText>, requested: AppLocale): LocalizedText?
}

data class LocalizedText(
    val locale: AppLocale,
    val summary: String,
    val detail: String?
)
```

If even `en` is missing for a `HIGH` / `PROHIBITED` ingredient, CI of the catalog pipeline **fails**. Fallback to empty comment is not acceptable for those levels.

`catalog_meta` records which locales were packed:

```sql
-- e.g. 'en,pl'
supported_comment_locales TEXT NOT NULL
```

The language settings screen can hide locales that have UI XML but no comment pack, or show a warning: “Ingredient explanations are still in English.”

## 5. Locale selection

```kotlin
data class AppLocale(
    val language: String,   // ISO 639-1, e.g. "pl"
    val region: String?     // ISO 3166, optional
) {
    val tag: String get() = if (region == null) language else "$language-$region"
}

enum class LocalePreference {
    FollowSystem,
    Pinned           // stored AppLocale
}
```

Stored in `user.sqlite`:

```sql
-- user_profile
locale_preference TEXT NOT NULL DEFAULT 'system',  -- 'system' | 'pinned'
pinned_locale TEXT                                 -- BCP-47 when pinned
```

### 5.1 Apply on each platform

| Platform | Mechanism |
| --- | --- |
| Shared | `LocaleController.locale: StateFlow<AppLocale>` drives comment queries and `UiText` resolution |
| Android 13+ | `AppCompatDelegate.setApplicationLocales` so the system per-app language setting stays in sync |
| iOS | Preferred languages override (`AppleLanguages` in the app sandbox) + recreate the Compose host if needed |
| Compose | Recompose from the root when locale changes (`key(locale.tag) { App() }`) so `stringResource` re-reads XML |

Do **not** only call `Locale.setDefault` and hope. Android configuration and iOS bundles must actually switch.

Default on first launch: **follow system**. If the system language is unsupported, UI falls back to `en` automatically via `values/`.

### 5.2 Settings UI

Preferences → Language:

- System default
- English
- Polski
- (later languages appear here when `values-xx` exists)

Changing language updates UI **and** comment queries immediately. Scan history ratings are stored as `DangerLevel` codes, so they relabel without migration.

## 6. Formatting (not just strings)

| Concern | Approach |
| --- | --- |
| Dates in history | `kotlinx-datetime` instant + locale-aware formatter (expect/actual or ICU via kotlinx) |
| Numbers | Locale decimal separators only where we show concentrations; GTINs stay digit strings |
| Layout direction | Compose `start`/`end`, `Row` with `Arrangement`, no hardcoded `ltr` except INCI tokens (chemical names stay LTR even in RTL UI) |
| Fonts | System fonts first; verify Polish diacritics (ą, ę, ł, ó, ż) on both platforms |
| Line length | German/Polish will be longer than English. Buttons: `Modifier.heightIn`, wrap or scale; screenshot tests in `pl` and a **pseudo-locale** |

INCI chips and barcode digits: force LTR (`TextDirection.Ltr`) so `CI 19140` does not reverse in Arabic later.

## 7. Translator workflow

1. Developers add keys only to `values/` (English) with XML comments for context.
2. CI **key-parity check**: every `values-xx` file has the same names as `values/` (or is allowed to omit keys and fall back — prefer **parity** so missing Polish is visible). Fail the build on missing keys in shipped locales (`en`, `pl`).
3. Optional: export XML → [Weblate](https://weblate.org/) / Crowdin. Keep XML as the source of truth in git.
4. Translators never edit Kotlin.
5. Editorial comments are a **CSV/JSON** in the catalog repo (`comments/pl/sodium-lauryl-sulfate.md` or a spreadsheet), compiled into `ingredient_comment`. That pipeline is independent of UI XML so a toxicologist does not need Android Studio.

### 7.1 Pseudo-localization (layout QA)

CI or a debug setting loads `values-en-rXA` (or a generated `values-zz`) that wraps strings as `[!!! Ŗḗşŭľŧ !!!]` and expands length by ~40%. Used in screenshot tests so banners and CTAs still fit.

### 7.2 Do not translate

- INCI / aliases used for matching
- Regulatory annex codes in data (`ANNEX_II`) — the **label** “EU Annex II (prohibited)” is a UI string
- AdMob unit IDs, URLs
- Log tags

## 8. Module placement

```
core/i18n/          # AppLocale, LocaleController, UiText, CommentLocalizer, formatters
composeApp/.../composeResources/values[-xx]/
```

`:core:i18n` has **no** feature knowledge. Features depend on it for `UiText` and locale. XML lives in `composeApp` (or `:core:common-ui` if resources must be shared across modules — CMP can generate `Res` per module; pick **one** resource module to avoid duplicate `Res` classes).

**Recommendation:** all UI XML in `:core:common-ui` (or a dedicated `:core:resources`) so feature modules can resolve strings without depending on `composeApp`. `composeApp` stays the shell.

## 9. Testing

| Test | Purpose |
| --- | --- |
| Key-parity Gradle task | `en` and `pl` have identical string/plural names |
| Forbidden-literal lint | Detekt / custom lint: no `Text("…")` with letters in `*/ui` |
| Plural fixtures | `unknownCount = 1, 2, 5, 12` for `pl` and `en` |
| Comment fallback | Ingredient with only `en` row, requested `pl` → English + optional fallback hint |
| Locale switch | Pin `pl`, recompose, assert a known key |
| Screenshot | Result screen in `en`, `pl`, pseudo-locale, with banner slot reserved |
| RTL smoke (later) | INCI chips stay LTR |

Domain tests stay in English identifiers only (`DangerLevel.HIGH`), never localized copy.

---

## 10. Store and legal copy

Play Console / App Store screenshots and descriptions are **not** `strings.xml`. Keep a `fastlane/metadata/<locale>/` (or equivalent) folder per store locale. Disclaimer **in the app** is `strings_legal.xml` and must match the meaning of the store disclaimer, but can be shorter.

Consent / UMP screens: use Google’s messaging in the user’s language where the SDK provides it; custom copy around it still goes through XML.

---

## 11. Adding a language (checklist)

1. Copy `values/` → `values-de/` (or empty files and translate).
2. Translate XML; run key-parity CI.
3. Add `de` comment rows to the catalog pipeline; pack `supported_comment_locales`.
4. Add the language to the settings list (`AppLocale` catalog in one place).
5. Screenshot the result and scan-permission screens.
6. Add store metadata if shipping in that country.

No Kotlin `when (language)` beyond registering the locale in the settings list.

---

## 12. Phase placement

i18n is **not** a polish-at-the-end task.

- **Phase 0:** `composeResources` + `UiText` + English XML + language setting stub + Detekt “no raw UI strings”.
- **Phase 1:** Result copy only via keys; plurals for unknown counts.
- **Phase 2:** Comment localizer + `pl` rows in the fixture DB.
- **Phase 7:** Complete PL review, pseudo-locale screenshots, store metadata.

If Phase 0 skips this, every screen will be rewritten to extract strings later.
